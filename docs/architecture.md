# 3X Control — Windows, C++17 / Qt 6

Нативное Windows-приложение Qt Widgets с тёмным интерфейсом, таймлайнами доступности, графиками онлайна и трафика. Подключается напрямую к нескольким 3x-ui. Первое открытие показывает пустой список с кнопкой добавления сервера; демо включается отдельно, его данные не сохраняются и сетевые операции отключены.

## Контракты

src/domain.h — структуры и Outcome<T>. src/three_x_ui_api.h — асинхронный API, src/local_store.h — SQLite. src/client_provisioner.h координирует создание общей подписки, src/backup_file.h проверяет и атомарно сохраняет бэкапы 3x-ui. src/main_window.cpp управляет интерфейсом и очередями опроса, src/chart_widget.cpp рисует графики, src/editor_dialogs.cpp проверяет ввод и формирует изменения клиента.

Сеть работает через QObject/QNetworkAccessManager/QTimer без блокировки GUI. Операции одного адаптера последовательны через очередь. Callback вызывается один раз и не вызывается после уничтожения QObject. Ошибки одного сервера не останавливают другие. GUI ограничивает каждую очередь опроса пятью активными серверами. Статус проверяется каждые 30с по умолчанию; следующий цикл не перекрывает предыдущий. Изменения клиентов могут выполняться во время мониторинга; изменение подключения ждёт окончания фоновых запросов. Пока открыта модальная форма, новый опрос не запускается. После изменения клиента перечитывается только его сервер. История хранится 30 дней, очистка выполняется при запуске и смене дня. Промежутки без замеров неизвестны. Секреты не попадают в журнал или сообщения об ошибках.

## 3x-ui 3.7.0 (подтверждено исходниками) и старый v2

URL = https://host:port/secret-base-path/; сохранять путь. validatePanelUrl: только https; http если config.allowHttp=true явно выбран пользователем; URL userinfo/query/fragment запрещены. Разрешать локальные серверы: это desktop app, SSRF веб-бэкенда здесь нет. TLS всегда проверять, ignoreSslErrors запрещён. RedirectPolicy ManualRedirectPolicy. Таймаут одного запроса 8с; response size limit 16MB.

Token: Authorization Bearer, X-Requested-With XMLHttpRequest. Cookie password login: GET /csrf-token (obj string), then POST /login JSON username/password/twoFactorCode + X-CSRF-Token. Старый v2 без csrf endpoint допускается только при 404; после успешного login обновить csrf token. Session cookies живут только в QNAM данного сервера. Auth/session ошибки сбрасывают loggedIn_; для безопасного чтения возможно повторное login в следующий опрос. Мутации никогда автоматически не повторять. Timeout мутации: результат неизвестен, обновите список перед повторением.

Modern readonly discovery GET /panel/api/clients/list. При 404/405 → Legacy; если success=false/auth/network error — не переходить в другую версию. Explicit flavor не обнаруживать. cached detection только для адаптера.

Common GET /panel/api/inbounds/list. V2 inbounds.settings — строка JSON с clients; clientStats email up down. V3 GET /panel/api/clients/list → массив flat ClientRecord с inboundIds и optional traffic. ClientRecord имеет numeric id, uuid (идентификатор доступа), password, email, subId, enable, totalGB (байты!), expiryTime (мс), flow, security, limitIp, limitHwid etc. parseInventory сохраняет opaque raw; id для доступа = uuid/строковый id/password; связывает protocol по inboundIds. Клиент может быть на нескольких inbound.

V3 GET /panel/api/clients/get/:email → obj {client:flat ClientRecord, inboundIds:[...], usedTraffic:bytes,...}. Для UPDATE преобразовать numeric id в строковый client id из uuid; model.Client ID должен быть uuid, НЕ database id! Сохранить неизвестные поля, uuid, password, subId, flow, security, limitHwid и ограничения. Перед update/delete/reset проверить свежий клиент с сервера: совпадение UUID/password/email и inboundIds. V3 глобальная запись: delete удаляет клиента со всех его inbound на ЭТОМ сервере; GUI сообщает это. update применять глобально, без inboundIds фильтра. Результат success=true обязателен.

POST V3 /panel/api/clients/add JSON {client:{id:uuid,password:password,email,totalGB,expiryTime,enable,subId,flow,security,limitIp:0,limitHwid:0,tgId:0,comment:"",reset:0},inboundIds:draft.inboundIds}. Vless/vmess id uuid, vmess security auto, trojan password random; создание shadowsocks не реализовывать без поддержки шифра inbound; выдавать понятную unsupported ошибку. Create перечитывает все inbound по id и проверяет enable и протокол. Flow Vision допускается только для исключительно VLESS. Глобальные V3 клиенты с inboundIds=null/отсутствующим/пустым массивом допустимы: показывать без привязок; повреждённый массив отклонять.

ClientProvisioner сначала получает свежий inventory каждого выбранного сервера и проверяет весь план до записи. UUID, пароль Trojan и subId создаются один раз для всего плана. Сохраняется полный per-server результат; сетевой отказ после первой записи не превращается в вымышленную атомарную транзакцию. Успешные записи не откатывать, мутации не повторять. Мастер-нода обрабатывается последней. V2 multi-inbound на одном сервере отклоняется при preflight. Уже существующий клиент допустим лишь при совпадении идентификаторов, subId, квоты, срока и состояния; добавляются только отсутствующие привязки, чужие записи не перезаписываются.

masterServerId — локальная настройка QSettings. Общая ссылка строится из subscriptionUrl мастер-ноды и subId выбранного клиента; при выборе записи другой ноды требуется совпадающий клиент на мастер-ноде. Установка этой настройки не меняет topology/nodes 3x-ui. Имена и секреты не используются как адреса или shell-команды.

## Бэкапы базы 3x-ui

GET /panel/api/server/getDb возвращает бинарную SQLite или PGDMP, а ошибка может возвращаться JSON с HTTP 200. Ответ ограничен 128 МиБ, проверяются HTTP, подпись и формат. POST /panel/api/server/importDB использует multipart-поле db и текстовое keepHostSettings=true/false. Ответ success=true обязателен, мутация не повторяется. Передача бэкапа использует более длинный таймаут; авторизация, cookie isolation, TLS и запрет редиректов такие же, как у остальных запросов.

SQLite проверяется через отдельный временный файл и read-only QSQLITE, quick_check, query_only и trusted_schema=OFF; обязательны таблицы settings/inbounds/users, clients необязательна для V2. PostgreSQL локально проверяется по заголовку без исполнения содержимого; полную проверку делает сервер. Чтение файла ограничивает размер до загрузки, сохранение использует QSaveFile. Временное SQL-соединение закрывается и удаляется после проверки.

GUI подтверждает конкретный файл, целевой сервер и keepHostSettings (по умолчанию true). До импорта получает, проверяет и атомарно сохраняет текущую базу цели в dataDirectory/backups; любой сбой этого шага останавливает импорт. После успешного импорта адаптер и сессия пересоздаются, inventory инвалидируется. Таймаут импорта — неизвестный результат; автоматического восстановления предыдущей базы нет. Внешние сертификаты/ключи/Geo-файлы отсутствуют в API-бэкапе. Локальная fleet.db приложения — отдельная база и не подходит для импорта в 3x-ui.

V3 POST /panel/api/clients/update/:email JSON полный model.Client. POST /panel/api/clients/del/:email. POST /panel/api/clients/resetTraffic/:email. V2 POST /panel/api/inbounds/addClient и /updateClient/:id form id=<inboundId>&settings=<string JSON {clients:[full client]}>. V2 POST /panel/api/inbounds/:inboundId/delClient/:clientId; reset /:inboundId/resetClientTraffic/:email. Параметры percent-encoded. UUID для vless/vmess; password для trojan; auth для hysteria. Для Hysteria без UUID auth используется как идентификатор проверки свежести, но никогда не записывается в поле UUID при изменении. sameIdentity проверяет auth наравне с UUID/password/subId. V2 перед любым изменением перечитать inbounds/list, проверить один inbound + client id/email, сохранить поля. И никогда не автоматически пробовать другую mutation endpoint.

GET /panel/api/server/status → obj cpu (проценты 0..100), mem.current/total, disk.current/total, netIO.up/down (cumulative bytes sent/received), netTraffic.sent/recv (bytes/s), uptime seconds, panelVersion, xray.version/state. Для older v2 допускается read-only fallback /panel/server/status только 404. xray.state running=Online, stop/error=Warning. Отсутствие поля = std::nullopt, не ноль. fetchStatus дополнительно POST onlines по известному flavor: V3 /panel/api/clients/onlines, V2 /panel/api/inbounds/onlines. Недоступный online = nullopt; метрики при этом не терять. Endpoint onlines читает состояние, безопасен. parseStatus не включает remote errorMsg (может содержать секрет).

ServerAction: restart → POST /panel/api/server/restartXrayService; geofiles → /updateGeofile; install → /installXray/:version; version regex ^v?[0-9]+(\.[0-9]+){1,3}$; без shell/SSH. UI подтверждение каждую потенциально отключающую операцию. Не добавлять обновление самой панели через install.sh: отдельная будущая возможность.

## SQLite и Windows DPAPI

База в QStandardPaths::AppLocalDataLocation/fleet.db. GUI передает путь в open. Именованное соединение SQLite, WAL, foreign_keys ON, busy timeout. DDL только при open в транзакции; PRAGMA user_version для простой миграции. servers: id PK, name/location/panel_url/subscription_url/auth/api/allow_http + credentials BLOB. credentials = DPAPI CryptProtectData QJson username,password,token, scope текущего пользователя, CRYPTPROTECT_UI_FORBIDDEN. TwoFactorCode никогда не записывать. DPAPI ciphertext с маркером версии. Сбой decrypt сообщить ошибкой, plaintext fallback запрещён. Windows Crypt32; на других OS сообщать unsupported. Не забывать LocalFree. Не выводить plaintext/credentialsCipher.

snapshots: autoincrement id, server_id FK cascade, at UTC epoch ms, health int, nullable metrics, versions, uptime, error; idx server_id/at. events: at, server_id, server_name, action, success, detail. appendSnapshot duplicate cutoff 20s per server; история time ordered, optional server filter (empty => all); load cap <=100000 разумные агрегированные окна GUI. removeServer удаляет локальное подключение и историю в транзакции; удалённую панель не трогает. Все SQL bindValue, ошибки propagate через Outcome. prune snapshots/events older30days. Демо не сохранять в базе.

## Подписки и представление 0.3

src/subscription_model.h/.cpp — чистая модель, не выполняющая сетевых запросов. SubscriptionGroup хранит исходные Client и provenance (serverIds), стабильный SHA256 key от length-prefixed subId/email или fallback credential/email. Пустые идентификаторы не объединяются между записями. Представитель выбирается по masterServerId, затем по порядку конфигураций серверов. Трафик представителя не складывается с зеркалами; итоговая сумма групп защищена от переполнения. Состояние Mixed возникает при различиях enable/quota/expiry. Протоколы объединяются из inventory для фильтрации. Фильтры применяются к целой группе, поэтому фильтр сервера сохраняет доступ к её остальным узлам. При обновлении выбор сохраняется по key, а сервер действия по serverId, независимо от сортировки.

Snapshot.onlineEmails/onlineDetailsAvailable хранят только живое наблюдение API и не пишутся в историю SQLite. В onlines принимаются непустые строки email, повторы удаляются, некорректный массив не превращается в ноль. Онлайн группы true при любом положительном наблюдении, false лишь при отрицательных известных наблюдениях всех участников, иначе неизвестен. Устаревшие/недоступные снимки не дают известный офлайн. Исторический онлайн берётся из мастер-ноды или выбранного сервера; без мастера в UI явно указана сумма, возможны повторы. CPU/RAM/отклик усредняются внутри минутных bucket. Неизвестные интервалы остаются пробелами на графике.

Группировка не расширяет область мутации: selectedClient выбирает ровно запись выбранной панели, по умолчанию мастера. CRUD использует исходную identity и fresh-read API. Несколько legacy-записей одной группы на выбранном сервере блокируют изменение через общую строку. Copy link использует представителя группы и подтверждённый subId мастера, независимо от панели действия. Размеры QSplitter сохраняются в settings.ini; при демонстрации настройки размеров не записываются. Тесты subscription/window проверяют уникальность, метрики, границы сроков, фильтры, стабильность выбора и сохранение размеров; core/provision/dialog проверяют Hysteria 2 и сохранность auth.
