# 3X Control

Отдельное Windows-приложение на C++17 / Qt 6 для управления несколькими панелями 3x-ui. Запускается на вашем ПК; отдельный сервер приложения не нужен.

## Запуск

Закройте предыдущую версию и откройте `dist/3X-Control-0.3/3X-Control.exe`. Оставьте рядом с приложением все DLL и каталоги из поставки. Установка Qt для запуска готовой сборки не требуется. Подключения и история из версий 0.1 и 0.2 сохраняются: путь локальных данных остался прежним.

1. Нажмите «Добавить сервер».
2. Введите полный адрес панели, включая её порт и скрытый путь: `https://vpn.example.com:2053/your-panel-path/`.
3. Выберите API-токен либо логин/пароль. Для управления клиентами API-токену нужны соответствующие права (обычно admin). 2FA-код вводится при подключении и не сохраняется; после окончания сессии понадобится новый код либо API-токен.
4. По желанию задайте **отдельный адрес выдачи подписок**, например `https://vpn.example.com:2096/sub/`. Адрес панели и адрес подписок — разные настройки. Без него управление клиентами работает, но копирование subscription URL недоступно.
5. Повторите для остальных серверов. В «Подписках» доступен общий список или фильтр по одному серверу.

HTTPS-сертификаты проверяются. Самоподписанный сертификат добавьте в доверенные сертификаты Windows. Вход по HTTP доступен только после явного включения в настройках подключения.

## Возможности

- Состояние API и Xray по всем серверам; CPU, память, диск, онлайн и отклик.
- Графики онлайна, приёма/передачи трафика, CPU/RAM и отклика API; интервалы 8 часов, сутки и неделя, выбор одного сервера или всей сети. Онлайн на графике всей сети берётся с мастер-ноды; при отсутствии мастера подпись предупреждает о возможных повторах.
- Создание одной подписки на нескольких серверах и инбаундах: дерево с галочками, «Выбрать все» и «Снять выбор». VLESS, VMess, Trojan и Hysteria 2 поддерживаются при создании. UUID, пароль Trojan, auth Hysteria 2 и subId общие для выбранных серверов. В API Hysteria 2 называется `hysteria`; ключ хранится в `auth`, а не в UUID.
- Изменение срока и квоты, продление на 30 дней, включение/выключение, удаление, сброс трафика.
- Одна строка на подписку с несколькими серверами, детали по каждому узлу, уникальные счётчики клиентов и трафик из записи мастера. Фильтры по серверу, протоколу, состоянию, сроку и имени; сортировка по трафику, сроку или числу серверов.
- Фильтры серверов по состоянию и расположению, сортировка по нагрузке и отклику, uptime и доступность за выбранный период.
- Растягиваемые разделителями блоки доступности, графиков и деталей подписки; размеры сохраняются.
- Выбор мастер-ноды и копирование общей ссылки с её адресом выдачи подписок.
- Бэкап полной базы 3x-ui, проверка файла и восстановление на другом сервере с предварительной копией его текущей базы.
- Перезапуск Xray, обновление Geo-файлов, установка указанной версии Xray.
- Журнал выполненных действий и ошибок; частичный отказ сервера не останавливает всю сеть.
- Отдельный деморежим с примерами графиков. Он не обращается к серверам и не записывает примеры в базу.

3x-ui 3.x использует глобальных клиентов: удаление клиента удаляет его со всех inbound на **выбранном сервере**. Другие серверы этой операцией не затрагиваются. Приложение подтверждает опасные операции. Перед изменением перечитывает клиента с сервера и сохраняет UUID, пароль, subId и остальные настройки.

## Мастер-нода и создание подписки

В «Настройках» выберите **Москву** как мастер-ноду. Если среди добавленных серверов есть ровно одна Москва, приложение выберет её при первом запуске версии 0.2. В её подключении задайте публичный адрес выдачи подписок. Приложение использует уже настроенное объединение нод в 3x-ui; выбор мастер-ноды в приложении не создаёт связи между серверами.

Нажмите «Загрузить клиентов», затем «Создать подписку». Отметьте нужные инбаунды на всех серверах, включая мастер-ноду для общей ссылки. «Выбрать все» отмечает только доступные, включённые инбаунды поддерживаемых протоколов. Поля клиента общие; квота применяется на каждом выбранном сервере, а не как единый лимит всей сети. Vision доступен только при выборе исключительно VLESS.

Перед записью приложение перечитывает все выбранные серверы и проверяет привязки и конфликты имён. Затем создаёт клиента с одинаковыми идентификаторами на каждом сервере. Результат отображается по серверам; уже выполненные операции при частичном отказе не откатываются. После таймаута сначала загрузите актуальный список. Повторное создание с тем же именем не перезаписывает другого клиента.

В старой 3x-ui 2.x для одной записи разрешён один инбаунд на сервере; для нескольких инбаундов обновите панель до 3.x. Глобальные клиенты 3.x без привязанных инбаундов тоже отображаются, с пометкой «Нет инбаундов».

## Общий список и статистика

Копии объединяются по одинаковым `subId` и email; когда `subId` отсутствует, используются идентификатор клиента и email. Только совпадение имени не объединяет разные учётные записи. В списке 10 клиентов на пяти серверах дают 10 подписок и 50 записей на серверах; связанные серверы видны в нижней таблице. Число инбаундов больше не занимает отдельную колонку общего списка.

Квота, срок и счётчик трафика берутся с мастер-ноды. Если её запись не загружена, используется первая доступная панель; источник указан в деталях и подсказке счётчика. Повторяющиеся счётчики не складываются. Различия в квоте, сроке или включении между узлами показываются как «Есть расхождения».

Выберите подписку и поле **«Действия через панель»** в нижнем блоке. По умолчанию используется мастер, если запись на нём загружена. Изменение, удаление, продление и сброс направляются в выбранную панель; дальнейшая синхронизация её нод зависит от настроек 3x-ui. Общая ссылка всегда использует мастер независимо от выбранной панели для действий. При нескольких записях одного клиента на API v2 изменение через общую строку блокируется, чтобы не изменить лишь часть его инбаундов.

Онлайн клиентов берётся из живого API и объединяется между серверами: один клиент учитывается один раз. Недоступные данные отображаются как «—», а не ноль; число подписок с известным онлайном видно в обзоре и подсказке. Исторический график онлайна использует мастер или выбранный сервер, поскольку сохранённая история содержит счётчики панелей. CPU/RAM и отклик графиков усредняются по доступным выбранным серверам. p95 в обзоре рассчитан по последним откликам панелей, это не измерение задержки VPN-туннеля. Уникальные подписки и карточки трафика отражают загруженный inventory; в разделе подписок он обновляется при периодическом опросе. Карточки подписок учитывают текущий фильтр, карточки обзора — всю сеть.

Тяните широкие разделители между блоками для изменения их размера. В маленьком окне страница прокручивается, чтобы оставались доступны фильтры и кнопки. Размеры блоков сохраняются при закрытии обычного режима; демонстрационные данные не меняют подключения и историю.

## Бэкап и перенос 3x-ui

В «Серверах» выберите исходный сервер и нажмите «Бэкап 3x-ui». Сохраняется база с клиентами, инбаундами, пользователями панели и настройками, хранящимися в 3x-ui. Поддерживаются SQLite `.db` и дамп PostgreSQL `.dump`; предел файла — 128 МиБ. SQLite проходит проверку целостности и таблиц 3x-ui. У PostgreSQL локально проверяется заголовок; целостность проверяет сервер при импорте.

Для переноса выберите целевой сервер → «Восстановить из бэкапа». Импорт **заменяет базу целевого сервера**. По умолчанию сохраняются его адреса, сертификаты и идентификатор ноды (`keepHostSettings=true`). Снимите галочку для переноса этих настроек из исходной базы. Перед импортом приложение скачает и сохранит текущую базу целевого сервера в `backups` внутри папки локальных данных. Если скачать, проверить или сохранить эту копию не удалось, импорт не запускается. Автоматического повторения импорта нет.

Бэкап содержит ключи клиентов и настройки доступа панели: храните файл в подходящем закрытом каталоге. Внешние файлы сертификатов, ключей и Geo-файлы, на которые база ссылается путями, в API-бэкап не входят — их нужно перенести отдельно. Пароли, токены, адрес и порт панели после импорта могут измениться; при необходимости обновите подключение. Бэкап 3x-ui не заменяет экспорт локальных подключений приложения. Возможность переноса между SQLite и PostgreSQL зависит от целевой версии 3x-ui.

## Данные

Настройки и история находятся в `%LOCALAPPDATA%/3XControl/3X Control/`. Точный путь можно увидеть в «Настройках» приложения. База SQLite — `fleet.db`, настройки интерфейса — `settings.ini`.

Учётные данные шифруются Windows DPAPI для текущего пользователя. Перенос базы в другую учётную запись или на другой ПК не переносит доступ к паролям. В этом случае заново задайте подключения.

Опрос выполняется, пока приложение запущено; интервал по умолчанию 30 секунд, настраивается от 10 до 600 секунд. История хранится 30 дней. Время, когда программа была закрыта, показывается как отсутствие измерений. Процент доступности рассчитан по собранным измерениям, а не по всему календарному времени.

Обновление самого пакета 3x-ui и SSH-команды в эту версию не входят. «Обновить Xray» обновляет только Xray-core через API панели. После таймаута изменяющей операции результат может быть неизвестен: сначала обновите список, прежде чем повторить действие.

## Сборка

Нужны PowerShell 7 (`pwsh`), Visual Studio Build Tools с C++ и Qt 6.8+ (`msvc2022_64`). Все библиотеки приложения динамические.

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -QtRoot C:\Qt\6.8.3\msvc2022_64 -Package
```

Если Qt установлен в `.tools/Qt/6.8.3/msvc2022_64` внутри проекта, параметр `-QtRoot` не нужен. Скрипт собирает приложение, запускает CTest и создаёт переносимую поставку в `dist/3X-Control-0.3`. Папку поставки можно задать параметром `-DistName 3X-Control-<версия>`.

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -TestsOnly
```

Для изолированного запуска/рендера:

```powershell
build\Release\3X-Control.exe --demo --data-dir build\smoke-data --capture build\overview.png
```

При разработке используются моделируемые ответы API и отдельные временные базы. На рабочих серверах пользователя создание и восстановление не запускались; первый перенос следует проверить на тестовой панели той же версии.
